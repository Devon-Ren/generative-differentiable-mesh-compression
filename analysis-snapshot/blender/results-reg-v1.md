## 读法

1. **权重错了约三个数量级**。顶点梯度范数比 |g_reg| / |g_main| 在 500 步时 ~1000（a、b）/ ~4800（c），b/c 在 29-30k 仍是 260-3100。Adam 按参数归一化，比值 ≫ 1 意味着顶点完全由正则驱动，渲染损失没有发言权：b/c 的 main loss 到 30k 还是 0.09-0.11（a 是 0.009），val 19 dB = 网格被 Laplacian + 法线项抹平成一团，面数从 2.3 M 掉到 0.4 M。要让正则"参与而不接管"，比值应在 0.1-1，即 w_lap / w_normal ≈ 1e-4 量级，不是 0.05。
2. **sliver 项只在最初 500-1000 步起作用**。a0 = 20 的 aspect 阈值只罚极细三角形；500 步时 loss 0.50（初始 soup 刚被拉成细条），1000 步后为 0（全部被推回 aspect < 20），之后整条训练里几乎不再有 aspect > 20 的面（sliver(>20) 0.00-0.02 %）。a 的 −0.9 dB 来自这段早期接管（ratio 1083）改变了生长起点，而不是"平滑的代价"。交付网格的 <10° 比例 28 → 9 %（真有效），但 dihedral、non-manifold 没有改善，因为没有任何项作用于它们。
3. **硬 jump filter 几乎没找到东西**：Delaunay 后 aspect q99 只有 8.3，按"aspect > 20 且最长边 > 6× 中位"只删了 11 / 7 / 1 个面；b/c 后期每轮删几千个是网格已经变形的结果。用户在 viewer 里看到的"跳跃连接"不是细长三角形，而是中等 aspect、跨越两个表面的面——需要按法线/深度不连续判，不是按形状。
4. **a 在 RD 上也不中性**：6.35 MB / 32.60 落在 v3 hull 之下（v3 在 6.35 MB 处插值约 33.2），被 λ6.2e-3 点 dominated。

## 结论（按 11/05 规则）

一次未"几乎成功"：a 只去掉了细三角形，表面平滑和跳跃连接两项都没做到；b/c 崩溃。→ 不进 CVPR，归 MeshSplat+++ 前期探索。已经学到、写进 +++ 笔记的东西：
- 权重标定必须按顶点梯度比做（目标 0.1-1），现成的 [REG] 日志就是为此；下一次（+++）的起点是 w_lap = w_normal = 1e-4、w_sliver = 1e-3、reg_from = 2000（跳过初始化阶段）、a0 = 8（罚到 min angle ≈ 7° 的面）。
- jump 过滤改用相邻面法线夹角 + 边长相对局部尺度的判据，或者深度不连续；aspect 单独不够。
- 可用的文件：train_rd_v4.py / mesh_reg_v1.py 保留，不再改；msv：$AN/viewer-v2/msv/lego-reg-{a,b,c}-lam0.00062.msv（a 可以看一眼细三角形减少的效果，b/c 不必）。
