Five triangles, every number: three growth rounds and one collapse round

A toy run of BudgetMesh with made-up but self-consistent numbers. Nothing is skipped: every formula is written, then the numbers are substituted, then the result is used in the next step. Vocabulary as in the paper: price λ, rate-aware growth (splits), rate-aware collapse, size controller, byte probe.

File size formula (the byte table):

R(V, F) = b_v·V + b_f·F + c = 6·V + 2·F + 100

Vertex count the aim can pay for (solve R = T·a with F = fpv·V):

V* = (T·a − c) / (b_v + fpv·b_f) = (500 − 100) / (6 + 2·2) = 400 / 10 = 40 vertices

Bytes one split adds (3 new vertices, each eventually with fpv faces):

ΔR = 3·(b_v + fpv·b_f) = 3·(6 + 4) = 30 B

The initial soup: 5 triangles, 15 vertices

Growth ended at V = 42 against the plan's V* = 40: the plan hit its aim within 5 %. Remember the aim was 500 B, not the 400 B target; the surplus is intended.

5. Stitching, and why the aim was 25 % high

MeshSplatting now joins the loose triangles into a shared-vertex mesh (its Delaunay step). In the toy: the 42 soup vertices become V = 38 mesh vertices (a few coincide or go unused) and the faces are rebuilt with fpv = 2: F = 76.

file now = 6·38 + 2·76 + 100 = 228 + 152 + 100 = 480 B (the byte probe measures this with the real encoder)

480 B is above the 400 B target, as intended. Had growth aimed at 400 B, the losses that are invisible before stitching (vertices that coincide, faces that end up cheaper, the final cleaning) would have left the file below target with no way to add bytes, because nothing can grow after stitching. Aiming high and collapsing back is the only direction that can be corrected.

6. The collapse round, every number

Step 1: how many bytes to remove, how many collapses

excess            = file − target = 480 − 400 = 80 B
bytes per collapse = b_v + 2·b_f = 6 + 2·2 = 10 B     (one vertex and the two faces on the collapsed edge disappear)
pairs needed      = 80 / 10 = 8
rounds left       = 1 → desired this round = 8 collapses

Step 2: score every edge

score(u,v) = ΔD_uv / ΔR_uv,  ΔD_uv = sum of the errors of all faces touching u or v,  ΔR_uv = b_v + (faces on the edge)·b_f

Do this for every edge of the mesh (76 faces → about 114 edges). Suppose the sorted scores begin:

Step 3: how many to collapse, and which

n_λ          = number of edges with score < λ·μ = 0.067   (μ = 1)        → 11 (e1 … e11)
rank threshold: admit about 4·desired = 32 cheapest edges as candidates   → thr_rank = score of the 32nd edge (say 0.12)
threshold used = max(thr_rank, λ·μ) = 0.12
gate: file (480) > target (400) → collapse this round
wanted = min( max(desired = 8, n_λ = 11), pairs that remove the whole excess = 8 ) = 8
per-round cap  = 25 % of V in this toy = 0.25·38 = 9.5 → 9  (not binding; the real runs use 15 % with 30 rounds)

Step 4: execute and account

8 collapses → V = 38 − 8 = 30, F = 76 − 2·8 = 60
bytes removed (exact, with the probe's prices) = 8·b_v + 16·b_f = 48 + 32 = 80 B
file = 6·30 + 2·60 + 100 = 180 + 120 + 100 = 400 B = target

Training continues for the remaining iterations with the optimizer state intact, so the merged vertices settle; the file is then encoded. In the real runs the collapse round repeats every 250 or 500 iterations, each time re-measuring the file with the byte probe and re-estimating where it will land, and skipping the round entirely when the estimate is already at or below target.
