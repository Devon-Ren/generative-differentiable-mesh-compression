Five triangles, every number: three growth rounds and one collapse round

A toy run of BudgetMesh that follows the real program step for step. Every quantity that is measured in the real run is measured here too, and changes when it is measured: the byte table, the survival of new vertices, the yield of the price, the bytes a collapse actually frees. Boxes in blue mark the moment a measurement replaces a prior. Nothing is skipped. Vocabulary as in the paper: price λ, rate-aware growth, rate-aware collapse, size controller, byte probe.

5. Stitching, the mesh probe, and why the aim was 25 % high

MeshSplatting stitches the soup into a shared-vertex mesh and the final cleaning removes faces nobody sees:
  37 soup vertices → V = 33 mesh vertices ; faces rebuilt: F = 66
mesh probe (the first probe on a real mesh: now all four numbers are measured)
  b_v = 6.0,  b_f = 2.0 (prior 2.5),  fpv = 66/33 = 2.0 (prior 2.5),  c = 100
  file = 6·33 + 2·66 + 100 = 198 + 132 + 100 = 430 B   (target 400: 7.5 % over, as intended)
b_f 2.5 → 2.0 and fpv 2.5 → 2.0: the stitched mesh costs less per vertex than the prior assumed. This is exactly the error the aim factor exists for: the growth plan priced each vertex at 12.05 B (prior table) but the stitched mesh costs 10 B per vertex, so a plan aimed straight at 400 B would have stopped at about 33 vertices and delivered only about 330 B, with no way to add vertices after stitching. Aiming 25 % high leaves a surplus the collapse round can remove; a shortfall cannot be repaired.

6. The collapse round, every number

Step 1: landing estimate, excess, collapses wanted

landing estimate: with earlier probes a trend would be extrapolated to the end of the opacity schedule (never downward); this is the first mesh probe, so estimate = probe = 430 B
excess                    = 430 − 400 = 30 B
bytes per collapse (prior, before any collapse is measured) = b_v + 2·b_f = 6 + 4 = 10 B
pairs that remove the excess = 30 / 10 = 3 ; rounds left = 1 → desired = 3 collapses
gate: estimate 430 > target 400 → this round acts (if it were ≤ 400, nothing would be collapsed)

Step 2: score every edge

score(u,v) = ΔD_uv / ΔR_uv,  ΔD_uv = sum of the errors of all faces touching u or v,  ΔR_uv = b_v·[u and v both in the delivered set] + b_f·(delivered faces on the edge)

Step 3: how many, and which

λ unchanged at 0.067: the count was binding, so the shadow price = largest collapsed score / μ = 0.038 is logged, and λ := 0.038 for any later round

Step 4: execute and account exactly

bytes actually removed (counted on the delivered set, with the probe's prices):
  e3: 1 vertex (6) + 1 face (2) = 8 ;  e1: 6 + 2·2 = 10 ;  e2: 6 + 2·2 = 10      → total 28 B
bytes per collapse measured = 28 / 3 = 9.3     (replaces the prior 10 for any later round)
V = 33 − 3 = 30,  F = 66 − (1 + 2 + 2) = 61
file = 6·30 + 2·61 + 100 = 180 + 122 + 100 = 402 B  = 1.005 × target
Bytes per collapse changed: prior 10 → measured 9.3. In the real run (30 rounds) the next round's "pairs needed" uses 9.3, and the next probe re-measures the file instead of trusting this arithmetic.

Training continues with the optimizer state intact; the file is encoded at the end. In the real run this round repeats every 250 or 500 iterations: each time the byte probe re-measures the file, the landing is re-estimated from the trend of probes, and the round is skipped when the estimate is already at or below the target.
