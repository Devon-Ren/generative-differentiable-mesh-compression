从 100 张照片到 10 MB 网格：一步一步走

用 Mip-360 的 room 场景、目标 10 MB、v9b 这一行真实日志里的数字贯穿全文。蓝色 = 上游 MeshSplatting 原样的步骤；橙色 = 我们插进去的步骤。先回答字节表的四个问题，再从 iteration 0 走到交付。

0. 先回答你关于字节表的四个问题

V 和 F 是什么？

V = 顶点表的行数。每个顶点一行：三维坐标 xyz、颜色（SH 系数）、一个不透明度参数。F = 面表的行数。每个面一行：三个整数，指向顶点表里的三行。这就是任何三角网格文件的结构（OBJ、PLY 都一样）。交付文件里，每个顶点要付"属性字节"（坐标 + 颜色），每个面要付"连接字节"（三个索引）。

size model 是做什么的？

它是一个算术公式，回答"如果我现在停下来交付，文件多大"：

R(V, F) = b_v · V + b_f · F + overhead

三块各自的字节加起来。b_v、b_f、overhead 不是猜的，是让真实编码器编一遍当前网格、读出每条流的字节数后算出来的（b_v = 属性流字节 ÷ V，b_f = 连接流字节 ÷ F）。room 10 MB 在 12500 步测得：b_v = 5.92，b_f = 1.80，overhead = 0.651 MB。

它用在哪里？

时刻用它算什么为什么需要
Phase A 每个生长间隔（1500…9500）反函数：目标字节 → 目标顶点数 V*控制器能动的只有"这一轮分裂多少个三角形"，这是一个顶点数。用户给的是字节数。必须换算
Phase A 每个间隔正向：当前 V → 预计多少 MB（日志里的 "projected 11.15 MB"）只是让人看懂进度，不参与决策
Phase B 每轮（12500…19500）一次边折叠省多少字节（b_v + 2 b_f），超出的字节 ÷ 它 = 要折叠多少对Phase B 能动的是"折叠多少条边"，又是一个计数，又要换算

反函数怎么来的？为什么要取反函数？

交付网格里面数和顶点数成固定比例：F ≈ fpv · V（Delaunay 网格 fpv 在 2.0 到 2.9 之间，room 是 2.01）。代进去：

R = b_v·V + b_f·(fpv·V) + overhead = (b_v + fpv·b_f)·V + overhead
⇒  V* = (R_target − overhead) / (b_v + fpv·b_f)

就是一条直线求 x。room 10 MB 在 9500 步：目标 R = 12.5 MB（为什么是 12.5 不是 10，见第 5 节），overhead 0.649 MB，b_v 6.42（soup 上测的），b_f 和 fpv 此时还只能用先验 2.0 和 2.5：

V* = (12.5e6 − 0.649e6) / (6.42 + 2.5 × 2.0) = 11.851e6 / 11.42 = 1 037 451 个顶点

日志原文：phase-A aim 12.50 MB = 1037451 vertices。为什么要反过来算：因为预算是字节，但生长这个动作只认"分裂几个三角形"。有了 V*，"还差多少顶点、还有几轮、这轮该分裂多少"就都是小学算术。

1. 输入与初始化（iteration 0）

上游步骤，我们不改。

输入是 100 多张照片（room 有 311 张，其中 1/8 留作测试）。先跑 COLMAP：得到每张照片的相机位姿，和一个稀疏点云（不是 dense；room 大约十几万个点，每个点带一个 RGB 颜色）。

MeshSplatting 对每一个点云点造一个三角形：

  • 中心放在这个点上；
  • 大小 = 2.23 × 这个点到最近邻点的距离（点密的地方三角形小）；
  • 朝向随机；
  • 三个顶点的颜色都等于这个点的颜色（只填 SH 的 DC 项，高阶 SH 全零）；
  • 三个顶点各带一个不透明度参数，初值 0.1。

所以 N 个点 → N 个三角形 → 3N 个顶点。每个三角形独占自己的三个顶点，没有任何共享——这叫 triangle soup（"一锅散三角形"）。此时 F = N，V = 3N，V/F = 3。

opacity 和 importance 是两回事

opacity（不透明度）importance（重要性）
挂在谁身上每个顶点一个每个三角形一个
是不是可学习参数是。有梯度，Adam 更新不是。是渲染器顺手记下来的统计量
怎么算sigmoid(参数)。渲染一个像素时，这个像素落在三角形内的位置按三个顶点插值出一个 α，再乘一个软边缘窗（sigma 控制，初始 1.0，到 30k 衰减到 0.0001 变硬边）。然后像 3DGS 一样前后 α 混合渲染每张训练图时，这个三角形对任何一个像素贡献的混合权重（α × 前面剩下的透射率）的最大值。跨所有视角、所有像素取 max，持续累积
直觉"这块玻璃有多不透""有没有哪个像素主要是靠它画出来的"。= 1 说明某个像素完全由它决定；≈ 0 说明它永远被别的三角形挡住或自己太透明，没人看见它
谁用它渲染；上游剪枝（顶点不透明度 ≤ 阈值 → 删三角形）上游剪枝（importance ≤ 阈值 → 删）；上游决定分裂谁（按 importance 抽样）；最终清理（importance ≤ 0.5 → 删）；我们的 probe 用同一条规则预判哪些面交付时还在

数值怎么定？

  • opacity 初值 0.1（init_opacity）。从 5000 步起上游给它加一个地板：activation 变成 floor + (1 − floor)·sigmoid，floor 从 0.1 线性抬到 24000 步的 0.9999。意思是：训练前半段三角形可以半透明地"试位置"，后半段被强迫全部变成不透明实心片。交付时所有面都不透明，所以文件里只需一个全局不透明度标量（Yao 批注 #12 问的就是这个）。
  • 剪枝阈值 prune_triangles_threshold = 0.235，5000 步后每 500 步加 0.01。顶点不透明度或三角形 importance 低于它 → 删。
  • 最终清理阈值 0.5：训练完后重新渲染所有训练图，importance ≤ 0.5 的面删掉。这一步删得不少（room 的模型 1.03M 顶点，交付时留 0.85–0.92M），而且它发生在 30k，Phase A 结束时看不到。这是后面"为什么瞄 12.5 不瞄 10"的根源之一。

2. 每一步迭代在做什么（0 → 30000）

上游循环。我们只在图中橙色的两个位置插入决策。

每个 iteration：随机取一张训练照片 → 用当前所有三角形渲染一张图 → 和照片比（L1 + 0.2·D-SSIM，外加法向、深度正则）→ 反传 → Adam 更新顶点坐标、SH、不透明度。渲染器同时顺手更新每个三角形的 importance（取 max）和 image_size（它在屏幕上多大）。

每 500 步，上游做"结构编辑"（改变 V、F 的操作）：

每 500 步上游做的事（顺序很重要）

  1. 剪枝（只在 start_pruning = 4000 之后，indoor 3000）：三角形满足任一条就删——三个顶点中最低的不透明度 ≤ 0.235(+ramp)；importance ≤ 0.235(+ramp)（训练图 < 500 张时才用）；在屏幕上太大（image_size > 1400 像素）。删完后没人用的顶点也删。注意：第一次剪枝通常删掉 soup 的 70–95 %——初始随机朝向的三角形大部分没用。
  2. 生长（每 500 步一次，从 densify_from_iter 之后开始到 10000 之前：室外预设 500 → 1000…9500 共 18 次；室内预设 1000 → 1500…9500 共 17 次）：上游原版是"把顶点数长到 1.23 倍，按 importance 抽样挑三角形，加上 100 个最大的，每个分裂成 4 个（三条边中点加三个新顶点），删掉父三角形"。我们把"挑谁、挑多少"换掉了（第 4 节），分裂的几何操作不变。
  3. 抬 opacity 地板（5000 后）。

上游"长到 1.23 倍"这个限制器（add_percentage）在我们版本里仍然生效：我们每轮分裂的数量不能超过它允许的 0.23 V 个三角形。室内预设是 1.27。

3. 字节是怎么被"测"出来的：byte probe

我们加的东西。它是整个系统的"尺子"。

问题：训练到第 9500 步，手里是一锅 soup，上游还要做 Delaunay、再训 2 万步、再清理一遍才交付。我现在怎么知道"最后会多大"？

答案：不猜，模拟交付一次。probe 做四件事，对训练模型零改动：

  1. 复制当前网格到一个副本。
  2. 在副本上模拟上游的最终清理：把 opacity 地板临时设成最终值 0.9999、超采样设成最终的 4×，渲染全部训练图，算每个面的 importance，≤ 0.5 的面删掉，没人用的顶点删掉。得到"如果今天交付，哪些顶点、哪些面会在文件里"（kept_v、kept_f 两个掩码）。
  3. 把副本存盘，调用交付时用的同一个编码器（子进程，K4096/R256 字典，room 的坐标精度 q14，DC 7 bit）真的编一遍。
  4. 读回：总字节、每条流各多少字节、留下的 V 和 F。算 b_v、b_f、overhead、fpv。

room 一次 probe 约 27 秒。一次训练做 7 + 15 次，约加 10 分钟。probe 读数与最终交付文件的误差：0.999 到 1.001（49 次全部）。尺子本身没有误差，有误差的是"今天的网格到 30k 时会变成什么样"。

4. Phase A：room 10 MB 的 17 个生长间隔

我们的决策点一。每 500 步一次，1500 到 9500。

先说清楚"λ 是什么"。上游原版挑分裂对象是按 importance 抽样。我们换成：每个三角形算一个性价比

ratio_t = ΔD_t / ΔR_t
ΔD_t：这 500 步里，所有训练图中"前景是 t"的像素的 L1 误差之和，除以图像的百万像素数，按视角平均。
      = 把 t 换得更细能最多消掉多少误差。
ΔR_t：分裂 t 要多付的字节。3 个新顶点 × (b_v + fpv·b_f) = 33 B（这个只定 λ 的单位，见下）。

ratio 大 = "这个三角形画得差又便宜，值得切"。λ 就是一条线：ratio > λ 的切，其余不切。 λ 高切得少，λ 低切得多。

Draft 1 的做法是人定 λ，网格长到哪算哪。现在的做法反过来：先决定这一轮该切多少个（k），再把 λ 定成"恰好让 k 个通过"的那条线（ratio 排序后第 k 大的值）。这叫 rank price。所以 ΔR_t 里的 33 B 常数并不决定切谁：它同时缩放所有 ratio 和 λ，排序不变。真正进字节预算的 b_v、b_f 是 probe 测的。

5. 为什么 room 瞄的是 12.5 MB 而不是 10 MB

这是整个系统里唯一一个真正"校准"出来的常数（OVER = 1.25）。要向 Yao 如实说。

9500 步时，V* 的公式里有三个量在 soup 上看不到，都会让最终文件比公式算的小：

看不到的量soup 上以为交付时实际（room）效果
κ：最终清理保留多少顶点全部12500 步时 853k / 1.03M = 0.83，到 30k 回升到约 0.9文件变小
b_f × fpv：拓扑字节 / 顶点2.0 × 2.5 = 5 B1.80 × 2.01 = 3.6 B文件变小
soup 上读的 b_v6.42网格上 5.92（soup 的坐标残差编得贵一点）文件变小

三项乘起来，没有 margin 的话 room 10 MB 会落在 0.80–0.88 × 目标，batch12 实测 0.877。10k 之后没有任何机制能加字节，但 Phase B 可以减。所以把误差故意放在"多了可以剪"的一侧：Phase A 瞄 1.25 × 目标（Mip-360 / T&T），Blender 1.1（它的 κ 是 0.995，拓扑接近先验）。这个 1.25 是从早期 sweep 的三项乘积算出来的，每类数据一个值。它补偿的是原则上在 11k Delaunay 前不可观测的东西；我们试过在副本上提前跑 Delaunay 来"看见"拓扑，但可见面集合在 opacity 地板抬升过程中还在继续长（室内 +10–50 %，室外 +5 %），提前看也看不全，所以没有做。

6. 10k → 12.5k：上游的 Delaunay

上游步骤，我们不改。

11000 步：把 soup 的 1.03M 个顶点当成点集，做 restricted Delaunay：生成一个共享顶点的真正网格，面数约 2× 顶点数。此后顶点数只会减不会加（上游再不分裂）。随后 opacity 地板继续抬，被迫变实心的三角形"摊开"（un-stacking）：原来叠在一起互相遮挡的面，地板抬高后前面的面变不透明，后面的面 importance 掉到 0 被清理；或者反过来，原来半透明没人算它重要的面，现在变成某些像素的唯一贡献者，importance 升上去。净效果是交付集合在 12.5k 到 24k 之间还在变，room 从 8.79 MB 变到 10.29 MB。

7. Phase B：room 10 MB 的 15 轮 λ-prune

我们的决策点二。每 500 步一次，12500 到 19500。

目的：Phase A 故意多长了 25 %，现在用真实编码器一轮轮量，多了就剪回去，剪的时候用同一个 λ 的反向规则：

折叠边 (u,v) iff ΔD_uv / ΔR_uv < λ
ΔD_uv：u、v 周围一圈面的误差之和 = 把这两个点合成一个会增加多少误差
ΔR_uv：合并后文件少的字节 = b_v（少一个顶点，仅当 u、v 都在交付集合里）+ b_f × 边上会消失的交付面数

和分裂完全对称："分裂"是误差大/字节小的切；"折叠"是误差小/字节小的合。合并时两个顶点的坐标、颜色、不透明度和 Adam 的动量一起平均到一个槽位——这是训练中折叠和训练后折叠的本质区别：优化器不失忆，剩下 1 万多步能把周围修好。

一轮里的完整操作，和 room 10 MB 每轮真实发生的事

  1. probe：真网格上实测 b_v、b_f、fpv、overhead，得到 r_meas = "今天交付多大"，以及 kept 掩码。
  2. 外推落点：r_meas 会变（第 6 节的 un-stacking），对历次 probe 做最小二乘，外推到 24000（地板抬完）。v9c 起斜率不允许为负（集合只会长，负斜率是噪声）。
  3. 要剪多少：excess = 落点 − 目标；每对折叠省 b_v + 2b_f ≈ 9.5 B（之后用上一轮实测的每对字节）；excess ÷ 9.5 = 总共要折几对；÷ 剩余轮数 = 这轮折几对。
  4. Gate：落点 ≤ 目标 → 这轮一对都不折。落点 > 目标 → 折 min(max(计划数, λ 线下的边数), 消掉全部超出所需的对数)。永远不剪过头。
  5. 选独立集、折叠、Adam 平均；如果是数量在约束（而不是 λ 线），λ := 实际折掉的边里最大的 score（shadow price），λ 跟着实际执行的价格走。
  6. 精确记账：这轮真少了多少交付字节，供下轮外推。

8. 20k → 30k → 文件

上游 + 我们的编码器。

20k 和 25k 上游开 2× / 4× 超采样（渐进式抗锯齿），24k 地板到 0.9999，所有面实心。30k 训练结束：重新渲染所有训练图，importance ≤ 0.5 的面删掉，存模型。然后我们的编码器跑一次：坐标量化到 q14 网格、编残差；连接用 cache-based 算术编码；每个顶点 45 个高阶 SH 系数换成"主字典 4096 选一 + 残差字典 256 选一"两个索引，字典在这个场景上 K-means 后对渲染误差再调 400 步；DC 7 bit。写成一个文件，10.29 MB。解码器独立程序，CPU 几秒，输出标准网格。

9. 一页总结：谁在什么时候用什么决定什么

时刻决定依据输入来自
每 500 步，1500–9500这轮切多少、切谁几何计划 → k；λ = 第 k 大 ratio；ratio > λ 的切V*（字节表反函数）、σ、yield、上游限制器
每 ≥1000 步，4000–9500更新字节表的 b_v、overheadsoup 副本 → 清理 → 真实编码器probe
每 500 步，12500–19500这轮折不折、折多少落点 > 目标才折；excess ÷ 每对字节 ÷ 剩余轮probe（全部四个量实测）+ 外推
同上折谁score = ΔD_uv/ΔR_uv 最小的先，ΔR 只算交付集合误差归因 + kept 掩码
30k—上游清理 + 我们的编码器

用户给的唯一输入是 10 MB。λ、V*、b_v、b_f、σ、yield 全是训练中算出来的。唯一人定的校准量是 Phase A 的 1.25 / 1.1 瞄高系数。
