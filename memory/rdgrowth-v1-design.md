Code (2026-10-18, user go-ahead): /mnt/project-files/analysis/rdgrowth/rd_growth.py (RDAccumulator, rd_select, rd_split; pure torch, CPU unit test in scratchpad passed) and train_rd.py (copy of upstream train.training; imports upstream via --lab <root>/upstream, chdir there, sets up.lpips_fn). Only change vs upstream: at each densification interval (500 steps, densify_from..densify_until=10000, phase A before restricted Delaunay at 11000) split triangle t iff dD_t/dR_t > lam, where dD_t = per-view-averaged sum of per-pixel L1 residual over pixels whose render_pkg['rend_ids'] == t ('error' mode; 'grad' = accumulated vertex grad norm; 'importance' = upstream multinomial sampling through same path = control), dR_t = 3 * bytes_per_vertex (--bytes_per_vertex, Room q14 ~10 B). Upstream growth limiter (add_percentage, max_points=4M safety) kept: lam decides which/when-to-stop, limiter caps speed. lam=0 = error-ranked, no price. Accumulator is masked along with prune_triangles / _prune_vertices (valid_tris computed before the call). Logs rd_log.jsonl (config / densify per interval: n_pass, n_split, ratio q50/q90/q99, valid_frac / delaunay / final) + rd_summary.json.

Upstream facts used: phase A soup with triangle pruning by min vertex opacity / importance (max_blending) / image size, _prune_vertices deletes triangles touching removed vertices (holes OK, Delaunay reconnects at 11000); phase B no vertex removal until final importance<=0.5 cleaning. So in phase A, bytes freed per vertex ~ constant; varying dR_v only exists in phase B (needs edge collapse + Adam state remap = v2, not in upstream; may justify touching the repo, user allowed).

Lambda units: per-view pixel-L1 mass per byte. Rough estimate mid-phase ratio ~1e-3, early ~2e-2 -> sweep {0, 3e-4, 1e-3, 3e-3, 1e-2, 3e-2}. Job block commands/rd-sweep-v1.md: writes both .py + rd-sweep-v1.sbatch (SCENE, IMAGES, LAMS, XYZ, BPV, MODE via --export; smoke 1200 it with lam 0 asserting valid_frac>0.5; per lam train -> run_garden FRACS=1.0 -> row "SCENE lam L RD-GROWTH-MODE | ... | grow: last split iter, V@delaunay, splits/interval" in /scratch/zr2245/analysis/rd-sweep-room.txt; outputs /scratch/zr2245/room-rd-error-lam<L>/). Submitted as room-rd-a (general: 0 1e-3 1e-2) and room-rd-b (tandon_advanced: 3e-4 3e-3 3e-2), ~1.5 h per lambda. Results: [[rdgrowth-room-lambda-results]]. Success bar (C3 in story v2): at equal vertices lam-split >= cap-only; lam monotone in vertex count; later same lam across scenes -> local slope ~ lam. If lam only moves the stopping point (ranking no better than importance), say so; method content then = scene-adaptive stop + v2 prune + allocator pricing.
