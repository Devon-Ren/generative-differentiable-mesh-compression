## 0.0 进度看板（10/15 更新；取代 0 节 TL;DR 里已过时的部分）

**当前论点（10/13，与导师对齐）**：differentiable opaque mesh 不需要独立的 per-vertex SH，这个表示高度冗余。方法 = **rate-aware 三杠杆**：RD collapse（轴 B，顶点数）+ RD index assignment（λ）+ neighbour-context index coder + precision allocation；两条 RD 轴合成 convex hull。原 TL;DR 的 "connectivity 是免费的 context（C1）" 已被 10/12 实测降级（邻居 context 对 index 值 ~2 bits/vertex，对 DC ≈ 0），"C3 用 QAT 追画质" 已被 10/13 实测否定（STE DC QAT 比 post-hoc 量化差 0.1 dB）。

**Room 上的 headline（解码 test PSNR，10/15 更新）**：原版 742 MB / 28.263 → 已测默认点 v0.8 + K4096 R1024 + q14/q7 = 28.79 MB / 27.902 / SSIM 0.8694（25.8×，−0.36 dB）；**10/15 实测默认点 v0.8 + K4096 R256 + q14/q7 + stage2-v2（const vertex_weight + ctx 索引编码）= 25.513 MB / 27.883 / SSIM 0.8686 / LPIPS 0.3703（29×，对 dense 41.40 MB / 27.934 为 −38 % 字节、−0.05 dB，SSIM/LPIPS 反而更好；对 historical collapse 26.88 / 27.347 少 1.4 MB 高 0.54 dB）**；payload：topology 9.83 / XYZ 5.80 / DC 3.72 / 主索引 3.11 / 残差索引 2.36 / banks 0.65 MB；低码率点 v0.7 + q7 = 25.39 MB / 27.725（比 historical collapse 少 1.5 MB 还高 0.38 dB）。stage2-v2 两项实测（v0.8 K4096 R1024 q14/q7 重导出）：vertex_weight 常量 −1.665 MB / −0.0001 dB（opacity 误差 9.7e-4），ctx 索引编码 −0.804 MB / PSNR 完全相同（6.969→6.165 MB，−11.5 %），合计 −2.47 MB（−8.6 %）零质量代价。hull v2：0.5 → q14/q7@1.98M → v0.7q7 → v0.8q7 → v1.0（analysis/rd/room-rd-hull-v2.png）。

## 0. TL;DR（10/09 原始版本；第 2、3 点已被 0.0 看板修订）

1. **现在的结果是扎实的 systems work，但按目前的写法还不够 CVPR。** 共享 SH codebook + residual、XYZ/DC 量化、meshopt reorder、parallelogram 类 XYZ 预测、edge-cache 拓扑编码，单看每一项在 3DGS compression（c3dgs、Compact3D、LightGaussian、CompGS、Reduced3DGS）或经典 mesh coding（Edgebreaker、TFAN、Draco）里都有对应物。审稿人会说"把 3DGS 的 tricks 搬到 mesh 上"。
2. **能撑起 CVPR 的 story：** *"Mesh connectivity 是免费的 context。"* 3DGS 是无结构点集，所以 HAC/ContextGS 要专门学 anchor/hash-grid 来造 context；MeshSplatting 天生带拓扑图。把它做成 **rate–distortion optimized、connectivity-conditioned 的 codec**，让 differentiable opaque mesh 解码后**还是一个标准 mesh**（能进 game engine、能做物理），这一点 3DGS compression 给不了。
3. **建议的三个 contribution**（第 3 节细讲）：
   - **C1 Graph-context appearance coding**：codebook index / DC 用已解码邻居做 context 的 arithmetic coding（目前这两个 stream 只走了 shuffle+Zstd）。
   - **C2 Render-aware RD simplification**：把 collapse 从启发式阈值改成 `ΔD + λ·ΔR` 的 RD cost，用 λ 扫出整条 RD 曲线，同时回应 PhD 的"三角形太多、render 不友好"，变成一张 #tri / FPS / PSNR 图。
   - **C3 Rate-aware end-to-end fine-tuning**：通过 differentiable mesh rasterizer 做 STE quantization + codebook QAT + 熵正则。这一项主要是用来**把画质追回来**。
4. **画质 gap 其实有两段，不是一段：** shared SH 本身已经 −0.33 dB / **LPIPS +0.039**（这比 PSNR 更显眼），collapse 再 −0.59 dB。最便宜的修复是 residual codebook 也要训练（现在是 `--steps 0`）、做 QAT，以及 collapse 之后用**原版 MeshSplatting loss 正常训练更多步**（现在是 800 步，而且每步位移被锁在 0.05×altitude 内）。
5. **⚠️ 时间：** CVPR deadline 一般在 11 月上中旬，离今天（10/09）大约只有 5 周。第 7 节分成「5 周必须做」和「有余力再做」。请先确认 deadline 和 GPU 预算。

## 0.5 用 Room 实测数据更新（10/09，来自 room-results-evidence 包）

### 41.4 MB 每个字段实际占多少（N = 3,193,592）
| stream | MB | 占比 | bits/vertex | raw bits/vertex | 判断 |
|---|---:|---:|---:|---:|---|

| DC q8 | 6.01 | 15% | 15.1 | 24 | 没有邻居预测 |

- **test 上 0.917 dB 里有 0.873 dB 是 simplification 造成的**；sharing + 编码在 collapse 路线里只占 0.044 dB。
- 800 步只追回了 collapse 损失的 18%（0.32 / 1.74）。所以真正要改的是 **collapse criterion** 和 **recovery**，不是 codebook。
- **10/12 appearance-only 重训**：只调 DC/SH（0 flips，几何不动）3000 步，val 28.972 → 29.319，约 2000 步后平台；比 Stage-2 的 800 步 constrained 只多 +0.03 dB。**颜色不是损失的来源**，追不回来的 1.4 dB 是几何/拓扑丢失。SSIM 恢复得多得多（0.8496 → 0.8795，原版 0.904），说明 collapse 的损失主要是结构/边缘，PSNR 对此很敏感。
- **10/12 per-view 分析（evidence coarse-summary，original vs coarse_independent，test 39 views）**：mean −0.873 dB，median 只有 −0.686；**5/39 个视角掉 >1.5 dB，这 5 个占总损失 42%**（DSCF4963 28.03 → 22.30，−5.7 dB；DSCF4699 −2.60；DSCF4723 −2.55；DSCF4867 −1.82；DSCF4811 −1.73）。损失高度集中在少数视角/区域 → 问题在 **collapse 选了什么被删**（纯几何 QEM 把某些视角里大面积可见的面给 collapse 掉了），不是重训不够。这直接支持 C2 的 visibility/RD-aware criterion。
- 第一次几何重训（world-unit lr 1.5e-4，无 trust region）发散：200k+ 面翻转、val 掉到 25.6。原因是 Adam 每步位移 ≈ lr，与梯度大小无关，sliver 三角形直接被翻。已改为 altitude-scaled 参数化（v = ref + h·x，h = 顶点最小 incident 高度，`--geo-unit altitude`，默认 geo lr 0 = appearance only）。几何重训第二遍（`--geo-lr 0.005`，altitude 单位）10/12 已跑：val 单调升到 **29.371**（+0.05 vs appearance-only），test **27.510 / SSIM 0.8642 / LPIPS 0.3875**，3000 步 0 翻转；val 最差视角 25.74 → 26.41。**结论：collapse 之后任何重训的天花板 ≈ val 29.4 / test 27.5，从 coarse_initial 只能追回 0.40 / 1.74 dB，剩下 1.34 dB 是拓扑丢失，只能靠改 collapse criterion（C2）。** 这两行可直接作为论文 "recovery upper bound" ablation。
- **10/12 C2 第一个实验已备好（`analysis/vis_collapse/`，见其 README）**：只把 collapse score 的几何项从"中位边长单位"改成"像素单位"（位置半径 × 每顶点 pixel_scale = 训练视角里的 max focal/depth），appearance 项换算成像素，按 cost 顺序 collapse 到与历史完全相同的 4,041,039 faces。派生的 native builder 在 uniform 模式下与原版逐 bit 等价（合成网格 merge 序列相同）。待 HPC 跑：footprint（GPU）→ coarse_vis（CPU 48 GB）→ coarse_finetune `--steps 0` / `--steps 3000`。判断标准：同面数下 coarse_initial val 是否明显高于 28.972，以及最差视角是否从 25.74 抬起来。
  - **实验 1 结果（10/12）**：纯 pixel_scale 在 Room 上无区分力——99.9% 顶点可见、pixel_scale 5–95% 分位只差 3.5×，删除集与历史重合 93%（Jaccard 0.87），28 px 阈值 = 历史 2 条中位边（14.15 px）。室内场景 focal/depth 不是信息来源。**实验 2** 改用渲染敏感度（Σ_views ‖∂(ΣI)/∂v‖、‖∂(ΣI)/∂DC‖，c3dgs 式）做每顶点几何/appearance 权重（`--geo-weight sens_pos --app-weight sens_dc --weight-power 0.5`），脚本已备好，待跑。
  - **实验 1 评估（10/12）：同面数下明显更差** — val initial 27.66 vs 28.97，最差 val 视角 21.9 vs 25.7，appearance-only 重训后 28.02 vs 29.32，test 26.50 vs 27.48。原因：远处（pixel_scale 低）顶点被允许合并到 ≈4.9 条中位边，近处只有 1.4 条；MeshSplatting 颜色在顶点上，顶点密度 = 纹理分辨率，远处顶点每像素承担更多纹理。**"屏幕空间位移 ≤ N px" 这种经典 LOD 指标对 vertex-coloured mesh 是错误单位 —— 可作为论文的负结果/动机。** 几何项必须保持在局部边长单位；实验 2 改为 `--base uniform` + 敏感度权重（除以 footprint 去掉距离因子）。
  - **实验 2 结果（10/12，同面数，未重训）**：中位边基准 × 渲染敏感度权重（`sens_pos`/`sens_dc` 除以 footprint，power 0.5，clip 0.1–10）：**validation 29.227 vs 历史 28.972（+0.26 dB），SSIM 0.8712 vs 0.8496（+0.022）**，test 27.13；但最差 val 视角 24.49 vs 25.74 变差。像素基准 × 敏感度 28.56（仍差）。结论：render sensitivity 作为"中位边单位"之上的权重有效，C2 方向成立；需要控制最差视角（提高 clip 下限 / 保护低敏感度但结构性的区域），并做 geo-only / app-only / power / clip 消融。
  - **实验 2 重训 + 完整交付（10/12）**：appearance-only 3000 步后 val 29.509 / SSIM 0.8878（历史 29.319 / 0.8795），test 27.498 / 0.8713 / LPIPS 0.3648（历史 27.479 / 0.8638 / 0.3871）；最差 val 视角 24.56 仍低于历史 26.4。走完 stage2 全链（sharing_after.convert → 400 步 appearance fit → export_asset q18/q8）：**25.466 MB，decoded test 27.429 / 0.8683 / 0.3712**，对比历史交付 26.884 MB / 27.347，dense 41.399 MB / 27.934 / 0.8618 / 0.3794。即：少 1.4 MB、PSNR +0.08、SSIM/LPIPS 都优于 41 MB 的 dense。阶段损耗：coarse 29.509 → sharing 29.121（−0.39）→ fit 29.392（+0.27）→ 量化 29.379（−0.01，48 个面翻转）。payload：top_stream 7.53 / XYZ residual 7.11 / features_dc 3.66 / app_mapping 2.73 / app_residual_mapping 2.40 / vertex_weight 1.25 / banks 0.76 MB。最差 test 视角 DSCF4939 16.05、DSCF4947 19.03、DSCF4963 22.64 没有改善 → 下一步是 clip 下限消融（0.3）与保护低敏感度结构区域。

**对 story 的影响（重要）：** "connectivity 是免费的 context" 这一句在原始资产上**不成立**——邻居相关性只值 1–3 bits/vertex。能成立的版本是 **"把表示训练成可压缩的"**：rate-aware assignment（提高邻居一致性）、RD collapse（减少面数，拓扑是最大头）、QAT。这和 HAC/CompGS 的 end-to-end 思路一致，mesh 特有的部分是 (a) RD collapse 作用在带拓扑的网格上、(b) 解码后仍是 engine-ready mesh。C1 从"核心 novelty"降级为 C3 的一部分。

**kNN 结果（10/12）：** mesh 边里只有 7% 落在端点的 4 近邻内，16 近邻内 21%，24 近邻内 28%；中位数 rank ≥24。一个正常曲面网格的 1-ring 基本都在 7 近邻以内，所以这说明**拓扑和几何几乎独立**：边连的是空间上并不相邻的点（多层互相穿插的三角形、长条 sliver）。结论：**拓扑没法从几何预测，只能靠减少面数（RD collapse）来降拓扑成本**，coder 层面的空间有限。这也是 collapse 的 motivation 图：画出 edge length / 局部点间距 的分布。

### ~~新的候选 contribution：Delaunay-predicted connectivity~~（10/12 实测否定，见上）

MeshSplatting 的拓扑来自 restricted Delaunay（论文 3.3），而且 mesh 建好后拓扑是固定的，只有顶点在动。假如最终的面大部分仍然是 *解码后的量化顶点的 3D Delaunay 四面体剖分* 里的面，那么 decoder 自己算一遍 Delaunay，encoder 只需要传「每个候选面选不选」的 membership bit（带 context）加少量 exception。这样拓扑可能从 30 bits/vertex 降到个位数 [推断]。这是**只有 MeshSplatting 才有的结构**，novelty 比通用的 graph context 更强。风险是 decoder 端 Delaunay 必须 bit-exact，需要用整数坐标 + exact predicates（例如 CGAL），不能用 qhull 浮点。

**验证脚本：** [`analysis/redundancy_stats.py`](/mnt/project-files/analysis/redundancy_stats.py)，CPU 就能跑，会输出 Delaunay 命中率、DC/index 用邻居预测后的熵、拓扑的流形性统计。

- 819.1 − 741.7 = 77.4 MB = 12 B × F，正好等于原 checkpoint 里每个 face 的 `importance_score / image_size / pixel_count`，而 `delivery.py` 正是把这三个字段当 AUX 丢掉的。

### 1.2 Protocol 和原论文对不上 [已核对]
论文 Table 8 里 Room 是 PSNR 28.52 / SSIM 0.873 / **LPIPS 0.271**；你的 baseline 是 28.26 / 0.883 / **0.339**。LPIPS 差这么多，几乎可以肯定是 VGG 和 AlexNet LPIPS 的区别（你的 README 写的是 VGG），另外分辨率/重训随机性也有影响。论文里需要：(a) 说明用的是哪种 LPIPS，(b) 最好 VGG/Alex 都报，(c) 所有方法用同一套 protocol 重算。

### 1.3 Bit budget：先量出来 [推断；已被 0.5 节的实测数据取代]
41.4 MB × 8 / N ≈ **104 bits/vertex**（含约 2 face/vertex 的拓扑）。collapse 版本是 26.9 MB × 8 / 2.006M ≈ 107 bits/vertex，基本一样，说明 collapse 只是减了数量，**每个 vertex 的编码效率没变**。粗估 raw（编码前）：

## 3. 方法：三个 contribution

### C1. Connectivity-conditioned appearance & attribute coding（核心 novelty，工程量小）
**假设：** 相邻 vertex 的 primary index、residual index、DC 强相关，因为表面颜色是连续的。
- **Traversal：** 复用拓扑解码的顺序（strip-fetch + edge cache）。解码 vertex i 时，它的已解码 1-ring 邻居 𝒩ᶜ(i) 已知。
- **DC：** `DĈ_i = median/mean(DC_j, j∈𝒩ᶜ(i))`（也可以像 parallelogram 一样用对顶点做预测），对 residual 做 adaptive AC，context 用邻居残差幅度分桶。
- **Index (z, u)：**
  - v1（不需要学习）：两档 context 的 AC：「是否等于某个邻居的 code」flag + 邻居 code 的 rank list（move-to-front），没命中再走全局 adaptive model。
  - v2（学习）：一个很小的 MLP/GNN 输入邻居 code embedding + 邻居 DC，输出 `p(z_i)`，按 scene 训练、权重算进 bitstream（参考 HAC 的做法，但 context 来自 mesh graph）。
- **Codebook-aware reassignment：** 在 assignment 时加 rate 项 `argmin_k ‖s_i − B_k‖² + λ_z · (−log p(k | 𝒩))`。这样邻居会倾向于选同一个 code，rate 会明显下降（这是 RD-VQ / ECVQ 在 mesh 图上的版本）。
- **期望：** index+DC 现在占的约 46 raw bits/vertex 能砍一半以上 [推断]。这是论文里最"干净"的 ablation：同一 asset，context on/off。

### C2. Render-aware RD edge collapse（把你的 hierarchy/collapse 正名）
现在：half-edge collapse，score = importance × max(几何半径/median edge, SH+opacity 半径)，阈值 error=2，然后在固定拓扑下做 800 步。
提议：
- **Cost：** `J(e) = ΔD(e) + λ·ΔR(e)`
  - `ΔD`：image-space 失真代理 = Σ_views（collapse 区域的 projected footprint × appearance 差）。可以用 attribute-QEM（xyz+DC+SH 拼起来的 quadric）× visibility 权重；也可以用 c3dgs 式 sensitivity，即 ∂L/∂attr 的累积，一次反传就能拿到。
  - `ΔR`：被删掉的 vertex/face 在当前 codec 下实际节省的 bits（用 1.3 的 per-stream bits/vertex 估）。
  - **Sub-pixel 优先：** 在所有训练视角下投影都 < 1 px 的三角形几乎零代价（restricted Delaunay 会产生大量小三角形，见论文 4.5），应该先 collapse 这类。我估计这一项本身就能拿走很大比例的 face [推断]。
- **Optimal placement：** endpoint collapse 改成 QEM optimal position + 属性插值（full edge collapse），失真更小。
- **λ sweep → RD 曲线**，并同时报 #tri 和 FPS。这同时回答了 PhD 的 render 顾虑：曲线上任意一点都是可用 asset。
- **（可选 C2+）Progressive bitstream：** collapse 序列天然就是 vertex-split records（Hoppe PM）。如果老板觉得 hierarchy rendering 意义不大，可以换个讲法："progressive / scalable transmission"，这在 compression 社区是标准卖点（PCGS 就是这么写的）。

### C3. Rate-aware end-to-end fine-tuning（主要用来追画质）
在 differentiable rasterizer 上联合优化（拓扑固定）：
- XYZ/DC：STE uniform quantization（q18/q8 当作 forward 噪声或 hard STE）。
- Appearance：B、R 可训；assignment 每 N 步按 C1 的 rate-aware 规则 reassign。**现在 residual 阶段是 `--steps 0`，这是最明显的白丢画质。**
- Loss：`L = 0.8·L1 + 0.2·D-SSIM + 原版 MeshSplatting 的 L_n / L_z（防止几何变坏）+ λ_R · R̂`，其中 R̂ 是 C1 context model 给出的 bits。
- 可选：用 dense independent 模型在大量 novel pose 上的渲染做 distillation pseudo-GT（便宜，通常有效）。

## 4. 怎么补回画质（按"性价比"排序）

**A. Shared SH 段（−0.32 dB / +0.039 LPIPS）**
1. 训练 residual codebook + DC，并定期 reassign（QAT）。现在 strict 1000 步、residual 0 步。
2. 加大 K：有了 C1 之后，index 的代价是 entropy 而不是 log₂K。可以扫 K₁ ∈ {4k, 16k, 64k}，在固定 rate 下比 PSNR。
3. **Per-vertex SH degree：** 很多 vertex 只需要 degree 0/1，让 code 0 = 全零 SH，C1 的 AC 会自动把它压得很便宜，省下的 bit 留给难的 vertex。
4. LPIPS 对高频 view-dependent 细节敏感：在 assignment proxy 里给 degree-3 系数加权，或者直接用 sensitivity 加权（c3dgs）。

**B. Collapse 段（−0.59 dB）**
1. **最强、最便宜的 baseline：** collapse 后直接用原版 `train.py` 的 loss 和 lr 在固定拓扑下续训 5k–10k 步，看能回多少。现在的 trust region（单步 0.01、总共 0.05×min altitude）是为了修"millions of flips"加的，但它也锁死了恢复能力。可以试：放开约束 + 加一个 orientation barrier loss（`−log(σ(n·n_ref/ε))`），或者 geometry lr 再降一个数量级而不做投影。
2. Sub-pixel-first + attribute-QEM optimal placement（C2）。
3. **Appearance 分辨率和几何解耦：** 三角形变大以后，vertex 颜色线性插值会丢纹理，这在原理上就是 collapse 掉点的主要原因 [推断]。便宜的修法：给被 collapse 影响的 face 加一个可选的 *face-level residual code*（每个 face 一个 index，用 C1 coding），只在 RD 划算的地方开。
4. Distillation（同 C3）。

**目标：** collapse 版本比 dense-compressed 低 ≤ 0.2 dB、size ≤ 0.6×；或者更好的写法：在 RD 曲线上，collapse 曲线全段 dominate 不做 collapse 的曲线（BD-rate 为负）。

