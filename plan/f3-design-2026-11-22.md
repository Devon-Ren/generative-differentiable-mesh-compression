# F3 设计：从照片构造"自由空间边界"（2026-11-22，新项目线，需要 GPU）

上游：`plan/memory-medium-2026-11-21.md`（目的与原理），`plan/f1-f2-feasibility-2026-11-21.md`（F1 理论 + F2 用真值几何的可表示性）。

## 0. F3 要回答的一个问题

**只给照片（和位姿），能不能构造出 F2 里那张闭合曲面，而且质量、大小、速度都站得住？**

F2 已经证明：给真值几何，表示没有障碍；剩下的误差来自我的贴合启发式（顶点只有 39–69 % 贴到了表面）。F3 用"渲染误差"代替真值几何来定位表面，这正好是 F2 缺的那一步。

## 1. 管线（和 F2c 一一对应，只把"真值"换成"照片"）

| 步骤 | F2c（真值） | F3（照片） |
|---|---|---|
| A. 每个视角的深度 | 真值 ray casting | **估计的深度**：前馈几何模型（Depth Anything 3 / VGGT），或作为上界对照的真值深度 |
| B. 雕刻 Ω，取闭合边界 | 全景深度，任一观测看穿即空 | 透视深度图，**多视角投票**（≥ m 个视角看穿才算空），容忍深度噪声 |
| C. 按 h = k × 到观看者距离细分 | 同 | 同 |
| D. 定位表面 | 沿视线贴到真值 | **可微渲染优化**：顶点位置 + 顶点颜色，最小化和照片的差 |

步骤 D 的细节（这是 F3 的核心，也是之前项目踩过坑的地方）：
- 渲染器：nvdiffrast，**不透明 z-buffer + `dr.antialias` + 4× 超采样**。P2/P2b 当年没开抗锯齿，结论被污染过，这次一开始就开。
- 几何梯度：不透明光栅只在轮廓有几何梯度，内部的几何靠两样东西：深度先验损失（来自步骤 A）和多视角光度一致性。
- 优化器：Laplacian 预条件（Large Steps / MODL 的做法），每一步只移动顶点，**不改连接关系**，所以曲面一直闭合、拓扑不变。
- 外观：先用逐顶点颜色（RGB + 1 阶球谐），和 F2 一致，便于对照；纹理留到后面。
- 天空：靠近"无穷远层"的顶点固定在无穷远，只学颜色。

## 2. 三个实验，从易到难，每一步只引入一个新变量

| 编号 | 数据 | 深度来源 | 新变量 | GPU-h | 通过标准（初版，待你定） |
|---|---|---|---|---|---|
| **F3-1** | 合成 Sponza 照片（我们自己渲染，位姿和真值几何已知），120 张，2 m 走动区域 | 真值深度 | 步骤 D（可微渲染能否把精度推过 F2c） | ≈ 0.5 | 区域内深度错误率 ≤ 3 %（F2c 是 5 %），测试视角 PSNR 不低于"同网格、逐顶点颜色"的上限 1 dB 以上 |
| **F3-2** | 同上 | **DA3 估计深度** | 深度估计误差 | ≈ 0.5 | 深度错误率 ≤ 6 %；所有视角洞 = 0 |
| **F3-3** | Mip-360 **room**（真实照片，COLMAP 位姿） | DA3 | 真实照片 | ≈ 1 | 见下 |

F3-3 的读数（和项目已有的数字直接比）：
- 标准测试视角的 PSNR / SSIM / LPIPS，对照 MeshSplatting FP32（room ≈ 28.5 dB：我们 --indoor 重跑后的复现与论文 28.52 相差 ±0.09）和 ByteMesh 在 room 上的率失真点（数字从 HPC 上的 rd 表里取）；
- **离开拍摄轨迹的闭合性**：在走动区域里随机放 50 个相机，统计"没有被任何表面覆盖的像素"。我们的按构造是 0；MeshSplatting 的 soup 在轨迹外会碎（10/26 截图），这一项是"记忆媒介"相对现有方法的核心卖点，第一次被量化；
- 文件大小（用 ByteMesh 的编码思路粗估即可）、从照片到结果的总时间。

F3-3 的通过标准需要你来定。我的建议是：PSNR 不低于 MeshSplatting 2.5 dB 以内，轨迹外洞 = 0，总时间 ≤ 10 分钟。理由是：单张不透明曲面加逐顶点颜色有已知的画质代价，这一步要证明的是"闭合、可走、快"，不是"比 3DGS 好看"。

合计约 2 GPU-h。

## 3. 上 GPU 之前在 CPU 上做完的事（遵守"先审后跑"）

1. 合成 Sponza 照片的渲染脚本（已有 ray caster，只加透视相机和导出），和数据格式检查（与 Mip-360 的 COLMAP 读入一致，或者写成 NeRF transforms.json 格式）。
2. 步骤 B（透视深度 + 投票雕刻）在合成数据 + 真值深度上跑通，拓扑、闭合性、深度错误率要和 F2c 一致。这一步纯 CPU。
3. 步骤 D 的代码用 CPU 能检查的部分全部检查：损失函数、Laplacian 预条件矩阵、天空顶点固定、"连接关系不变"的断言；在一个几百个顶点的小球上用 PyTorch 的 CPU 光栅（或手写的小渲染器）跑几十步，确认梯度方向对、损失下降。
4. 每个 GPU 任务开头有自检：数据、深度文件、输出目录、nvdiffrast 能否 import，任何一项失败都在训练前退出并打印原因。

## 4. 需要你决定 / 确认的事

1. **DA3 能不能装**：HPC 上要 pip 安装 Depth Anything 3 并从 HuggingFace 下载权重（login 节点有网，计算节点通常没有）。不方便的话，F3-2 / F3-3 先用 VGGT，或者先用"已经训练好的 MeshSplatting room 模型渲染出的深度"作为替代上界，DA3 留到后面。
2. **代码怎么上 HPC**：按以前的习惯用 heredoc 粘贴块（代码大概几百行，会很长）；还是在 HPC 上 `git clone -b code-backup`（需要 HPC 能访问这个仓库）？
3. **F3-3 的通过标准**（上面的建议是否接受）。
4. **场景**：F3-3 只做 room（室内、相机在里面），还是加一个 lego（物体、相机在外面）？加 lego 约 +0.5 GPU-h。

## 5. 不做的事（这一轮）
- 单张照片（等 F3-2 证明估计深度可用之后再做，它还需要处理视野外的"膜"）；
- 纹理、字节定价下的细分、ByteMesh 编码；
- 薄结构 / 植被 / 动态。

## 6. 决定（2026-11-22，用户确认）
- DA3 在 login 节点安装（login 有网，GPU 节点没网）。
- 代码以 zip 交付，附放置位置、解压和启动的终端命令；不走 GitHub 克隆。
- F3-3 按**两级标准**：(1) 可行性：PSNR ≥ MeshSplatting（room ≈ 28.5 dB）、离轨迹洞 = 0、总时间 ≤ 10 min；(2) 项目画质目标 ≥ 3DGS（room 30.6–31.7 dB），作为下一阶段目标；F3-3 同时把与 3DGS 的差距拆成抗锯齿 / 颜色表示 / 几何三部分量化。
- 不加 lego。
- 均匀雾 / 空气透视按命题 1' 处理（两个全局参数）；room 无雾，F3 不涉及。
