# 我们可能已经接近的那个"general, elegant"东西：bytes 只买多视角证据（2026-10-29）

用户问（10/29）："u sure there is nothing we can look for? … i think we are already close to something general, elegant, but just don't know?"
这份文档是回答：把项目里三件各自成立的事实放到一起，它们是同一个原理的三条腿；其中一条腿今天用现有数据做了核对；缺的那条腿有一个 1–2 GPU-h 的实验。

## 1. 三个已测事实

1. **码率放进环里 ≫ 事后压缩**：同顶点数，train-at-budget 比 post-hoc collapse 高 +0.3..+4.3 dB（7/7 场景）；λ-growth 在预算紧时比数量 cap 高 +0.25 dB（Room 0.5M）。字节在训练环里是一种正则化，不是后处理。
2. **多买的字节在"残差底"高的场景只买到训练视角**（R9）。今天用 11 个场景的 v3 两点（λ 1.85e-3 / 6.2e-3）核对：定义 g = Δtest / Δtrain（从 λ_hi 到 λ_lo 多花字节换来的 test 增益占 train 增益的比例），残差底用 λ_hi 点的 train RMSE 代理（10^(−PSNR_train/20)）：

| scene | train RMSE @λhi | Δtest | Δtrain | g |
|---|---|---|---|---|
| room | 0.035 | +0.62 | 0.98 | 0.63 |
| kitchen | 0.045 | +0.84 | 1.14 | 0.73 |
| counter | 0.050 | +0.53 | 0.85 | 0.62 |
| bonsai | 0.055 | +0.49 | 1.18 | 0.41 |
| stump | 0.059 | +0.59 | 1.03 | 0.58 |
| garden | 0.064 | +0.85 | 1.25 | 0.69 |
| truck | 0.069 | −0.17 | 0.29 | −0.57 |
| bicycle | 0.071 | +0.33 | 0.69 | 0.48 |
| train | 0.096 | −0.02 | 0.10 | −0.14 |
| flowers | 0.097 | −0.14 | 0.47 | −0.30 |
| treehill | 0.130 | +0.08 | 0.59 | 0.13 |

Spearman(RMSE, g) = **−0.73**（n = 11）；g 最低的四个场景（truck, flowers, train, treehill）是残差底最高的五个里的四个，bicycle 是例外。等价表述：Spearman(test PSNR @λhi, g) = +0.71。
   读法：残差底高 = 这个 model class（不透明 mesh）解释不了的那部分残差大；growth 的价值信号 dD 是按视角累计的残差质量，它分不清"3D 上真的缺一块几何"和"这一视角拟合不上"，于是在残差底高的场景里 split 去追后者，字节买到 train 不买到 test。
3. **拓扑是真信息**（方向 A，10/26–27）：训练出的 soup 不是顶点位置的函数；它的自由度就是画质。所以"少传"这条路到头了，剩下的只能是"买对"。

## 2. 今天排除掉的那个"优雅"版本：λ = 噪声尺度（MDL）

最诱人的解释是 MDL：把 λ 当成数据噪声决定的描述长度交换率，growth = 贪心 MDL 模型选择，λ* ∝ 残差尺度 b，这样 λ 不是旋钮而是数据的属性。排序检验（上表）和它一致，但定量不成立：按 Laplace 噪声算，一次 split 省下的残差码长 = κ·N·dD·1e6/(b ln2) bit（N ≈ 250 视角，κ = split 能消掉的归属残差比例 ~0.3，b ≈ 0.03），对应 λ_MDL ≈ 8 ln2·b/(κ N 1e6) ≈ 2e-9，比我们用的 λ（1e-3..1e-2）小六个数量级。原因很清楚：训练图像的残差码长（~GB 量级）远大于模型码长（MB 量级），按训练数据描述长度，几乎任何 split 都"值"。**所以我们的 λ 不是描述长度的价，而是泛化的价**：它定的是"一个字节要买到多少能迁移到新视角的改进"。这一步把"优雅"从 MDL 挪到了下面这句话。

## 3. 存活的原理（一句话）

**"Grow by paying bytes for multi-view evidence."** 字节要买的不是某个视角的残差，而是多个视角一致支持的残差（= 能用一次 3D 改动解释的残差）。价格 λ 一个、所有场景通用；在残差底高的场景里，一致的残差占比低，growth 自动早停——"尺寸是输出"就从"λ 决定"变成"数据的证据量决定"。

它把三条腿接起来：事实 1 说价必须在环里；事实 2 说价值信号必须区分可迁移和不可迁移的残差；事实 3 说不能再靠少传来省，只能靠买对。它和 design-space 文档里的主线 B 是同一个机制，但地位不同：B 作为"修 R9 的技巧"是支撑项；作为"11 场景可预测规律背后的机制"它是论文的论点。

## 4. 可证伪的预测（都用现有流水线能测）

P1 同一个 λ 下，残差底高的场景（flowers/truck/train）资产变小、test 不降或上升；残差底低的场景（room/kitchen）基本不变。
P2 等字节下 train−test gap 缩小（买到的字节更"诚实"）。
P3 上表的 g 在新价值信号下整体上移、和残差底的相关性减弱（规律被机制吸收）。
P4（通用性）3DGS 的 densification 也是按视角累计梯度定价（"pay per view"）；加同样的一致性门控应同样早停并改善泛化——原理不依赖 mesh。

## 5. 机制（最小改动，rd_growth_v2 的 accumulator 多三个数组）

每个三角形 t 除了残差质量 m_t 之外，累计：可见视角数 N_t、有效残差视角数 n_t（该视角内归属残差超过阈值 τ·中位数）、以及逐通道**带符号**的残差均值和 s_t = Σ_v s_{t,v} 与 Σ_v |s_{t,v}|。一致性 c_t = |Σ_v s_{t,v}| / Σ_v |s_{t,v}| ∈ [0,1]（所有视角同号 → 1；正负抵消 → 0）。价值信号改为 dD'_t = m_t · c_t^α（默认 α = 1）或 m_t · (n_t/N_t)。规则不变：split iff dD'_t > λ·dR_t；prune 的 ring-residual 同样换成一致残差。形式和 α 在 Room + flowers 上定一次，在第三个场景确认，不按场景调（10/13 规则）。

## 6. 运行清单与判据

- 探针（1–2 GPU-h，general）：Room + flowers，λ 6.2e-3，v6 = v3 + 一致性价值信号；可选加 λ 1.85e-3（共 4 跑，~2.5 GPU-h）。判据：P1 在 flowers 成立（字节 ≤ v3 且 test ≥ v3 − 0.05），Room 等字节 test ≥ v3 − 0.05，P2 两场景 gap 缩小 ≥ 0.1 dB。成立 → 扩到 11 场景 × 1 λ（~8 GPU-h）重画表 1/图 2；不成立 → g 表仍可作为分析节的"bytes that don't generalise"段落。
- 截稿后 / 不要截稿的"worth a shot"：P4 在 3DGS densification 上复现（1 场景 1.5 GPU-h，成立再 3 场景 ~6 GPU-h）。两个表示上都成立，就是一篇"growth-based scene representations should pay bytes for evidence"的论文，而不是一个 codec。

## 7. 诚实的不确定性

- 排序检验只有两点/场景，Δtrain 小的场景（train 0.10、truck 0.29）g 噪声大；bicycle 是反例。
- 一致性门控可能压制稀疏视角下的合法细节（设计空间文档已写），τ 和 α 必须一次定死。
- 即便 P1–P3 成立，审稿人仍可说"这是 densification 准则的一个权重"；让它成为论点的是跨场景的可预测性（上表）和 P4 的通用性，不是机制本身的复杂度。
