# 3D 记忆媒介：从"一个闭合的壳"出发（2026-11-21，新项目，与 CVPR ByteMesh 线严格分开）

## 0. 宗旨

把 3D 场景做成一种**新的记忆媒介**，取代 2D 照片成为人们保存数字记忆的默认方式：拍下来、立刻能看、能走进去、能拿起里面的东西，而且像 JPEG 一样小、一样到处能打开、几十年后还能打开。

这份文档的立场：**不是把别人的表示拼在一起**（之前 +++ 文档里的"流形 mesh + 面纹理 + alpha 卡片 + 位移"就是一种拼凑，本文不再沿用）。先定目的，再从目的推设计需求，再从需求推出**一个**基本原理，表示和训练都从这一条原理长出来。

## 1. 从目的推出的设计需求

"照片"之所以成为记忆的载体，是因为它满足了下面这些条件。3D 记忆要取代它，每一条都不能比照片差，再加上照片做不到的两条（R8、R9）。

| # | 需求 | 可测的标准（初版，待讨论） |
|---|---|---|
| R1 | 随手拍 | 输入从 1 张照片到一段手机视频；不需要位姿、标定、遮罩 |
| R2 | 立刻能看 | 第一版可看结果 ≤ 10 s；精修 ≤ 5 min（单卡），长远在端上 |
| R3 | 和照片一样小 | 单张照片生成的结果 ≈ 照片大小（几 MB）；一个房间 ≤ 20 MB |
| R4 | 到处能打开 | 交付物是标准不透明带纹理 mesh（glTF），手机浏览器 60 fps，不需要专用渲染器 |
| R5 | **永远不破** | 任何视角下没有洞、没有漂浮碎片、没有"世界的尽头"——由构造保证，不靠调参 |
| R6 | 忠实 | 在拍摄视点附近≈原照片；离开拍摄轨迹时画质平滑下降，但始终合理 |
| R7 | 渐进 | 以后补拍几张，同一个文件继续长；每个阶段的文件都是完整可用的；自带 LOD |
| R8 | 能走进去 | 漫游时有碰撞（不会穿墙、不会掉出世界） |
| R9 | 能拿起来 | 场景里的物体可以被分离出来，单独旋转查看 |

几条推论：
- R4 + R5 + R8 ⇒ 交付物必须是**闭合的表面**。三角 soup（MeshSplatting）、高斯、NeRF 都违反 R5/R8：离开轨迹就碎（10/26 的截图），也没有可以碰撞的面。
- R6 ⇒ 质量的定义不是"测试集 PSNR 排行榜"，而是"**按观看可能性加权**的保真度"：人回看记忆时，绝大多数时间站在当初拍摄的位置附近。字节应该花在那里。
- R7 ⇒ 表示必须能从**极少证据**开始就是完整的，然后随证据增加而细化，而不是"证据够了才成形"。

## 2. 基本原理：场景 = 相机所在的自由空间的边界

你提出的"从一个闭合的球开始，相机在里面就是室内/室外，相机在外面就是物体"，可以统一成一句话：

> **相机永远站在自由空间（空的、看得穿的空间）Ω 里。一段 3D 记忆就是 Ω 的边界 ∂Ω，法向朝向 Ω。**

- **相机在里面（室内、室外、街道）**：Ω 是包住所有相机的一个腔，∂Ω 是一个闭合的壳——墙、地、天花板、远处的树、天空，都在这一张壳上。
- **相机在外面（围着一个物体转）**：Ω 是物体外面的空间，∂Ω = 物体的闭合表面 + 远处的一层背景壳。
- **两种同时出现**（在房间里绕着桌上的杯子拍了一圈）：Ω = 房间减去杯子，∂Ω = 房间壳 + 杯子壳。不需要"模式开关"，只是 Ω 的边界有几个连通分量。

为什么这一条能直接满足需求：
- **R5 由定义保证**：一个封闭区域的边界一定是闭合的。从 Ω 内部的任何位置看出去，每条视线都会打在 ∂Ω 上：不会有洞，也不会有"漂浮物"（漂浮物 = Ω 内部的东西，按定义不存在）。
- **R8 由定义保证**：碰撞 = 不能离开 Ω。漫游天然有边界。
- **R9 是同一原理里的一次拓扑操作**：桌上的杯子在房间壳上先是一个"鼓包"；证据显示杯子和桌面之间有空隙时，鼓包被"掐断"（pinch-off），就成了一个独立的闭合物体，可以拿起来。物体模式和场景模式之间的转换，就是这一次掐断。
- **R7**：壳从第一刻起就是完整的。没有证据的地方只是一张光滑的"膜"，有了证据就变形、细分；补拍 = 继续变形，文件格式不变。

### 2.1 "无界"不是问题：无穷远就是一个坐标

室外的天空和远山在无穷远，但这不需要额外的"背景模型"：
- 以拍摄中心为原点，壳上每个顶点用（方向 d，逆距离 ρ）表示，位置 = d / ρ。用齐次坐标写就是 (d, ρ)：**ρ = 0 就是无穷远的点**。
- GPU 光栅化本来就吃齐次坐标（clip 空间的 w），用无限远平面的投影矩阵，ρ = 0 的顶点可以直接画。所以"天空"就是壳上 ρ → 0 的那一部分，和墙是同一种三角形，同一个文件格式。
- 在 ρ 空间里，整个世界是有界的（ρ ∈ [0, ρ_max]）。这就是"即使场景无界，也有办法让它有界"的具体做法；而且逆深度本来就是 SLAM / 单目深度里条件数最好的参数化。

### 2.2 内还是外：由相机自己决定

不需要用户选，也不需要按数据集手设。看相机光轴的走向：
- 光轴**汇聚**到一个共同目标（∑ 光轴 · (目标 − 相机中心) > 0）⇒ 外部视角，初始化一个"物体球" + 远处背景壳；
- 光轴**发散**（从一个区域向四周看）⇒ 内部视角，初始化一个包住相机的球；
- 混合轨迹 ⇒ 两种都有（房间壳 + 物体球），后面由证据决定物体球是保留还是并回墙上。

## 3. 怎么从一个球长成一段记忆

整个生长过程只有一个对象：一张（或几张）闭合、带纹理的三角网格。按证据从少到多分三个阶段，**每一阶段的结果都是完整的、能交付的文件**（R7）。

**阶段 1：径向膨胀（1 张照片就能做，秒级）**
- 壳上的顶点只沿方向 d 移动，只优化 ρ。这时候壳是一张"360° 深度全景"：从拍摄中心看是星形的。
- 初值来自单目 / 前馈几何模型的深度（如 Depth Anything 3、VGGT，同时给出位姿）。照片拍到的部分立刻成形；没拍到的方向保持为光滑膜（闭合、低细节、几乎不占字节）。
- 外观：壳在这一阶段的自然参数化就是"方向球面"，纹理就是一张等距柱面或立方体贴图——**也就是那张照片 / 全景照片本身**。从拍摄点看，3D 记忆和原照片一致（R6）：这个媒介向下兼容照片。

**阶段 2：展开（多张照片，有视差以后）**
- 视差会暴露星形假设之外的东西：沙发背后、桌子底下。这些地方给顶点放开切向自由度，壳开始"折叠"进去。
- 信号是可见性：如果某条视线穿过了壳认为是"实心"的地方（观测深度 > 壳的深度），说明那里其实是自由空间，壳要往外推。这就是 space carving 的思想，但作用在一张可微的连续表面上，而不是体素上。
- 外观开始需要多个纹理块（图集），参数化在交付时再整理（xatlas 之类），训练时用面上的局部坐标。

**阶段 3：拓扑事件（低频、离散）**
- 桌腿之间产生"把手"（亏格增加），杯子从桌面上掐断（连通分量增加）。这两件事不能靠梯度连续完成。
- 做法：和 MeshSplatting 在 11k 步做一次 Delaunay 一样，把拓扑改变做成**少数几次离散事件**：当壳的两部分在自由空间证据的夹逼下距离小于 ε 时，在局部做一次手术（打通 / 掐断），然后继续连续优化。这是本项目最大的技术风险，见 §5。

**贯穿三个阶段的法则：字节只买证据（ByteMesh 原理的延续）**
- 每一个候选操作（细分一个面、放开一块的切向自由度、提高一块纹理的分辨率、一次拓扑手术）都用同一个价格比较：ΔD / ΔR，R 是真实编码器量出来的字节（ByteMesh 的 size probe）。
- 和 ByteMesh 唯一的不同：ΔD 按**观看可能性**加权（R6）——离拍摄轨迹越近、被越多视角看到的区域，误差越值钱。
- 用户唯一的旋钮仍然是目标大小 T。

## 4. 这条路和已有工作的关系（诚实版）

| 已有工作 | 和本文原理相同的部分 | 本质区别 |
|---|---|---|
| MeshSplatting / Triangle Splatting+ / ByteMesh | 可微不透明三角形；ByteMesh 的字节定价 | soup 没有"自由空间"概念，所以不闭合、离开轨迹就碎；本文用 ByteMesh 的定价，但对象换了 |
| 3D Photo / 分层深度图（Shih 2020 等） | 单张照片 + 深度 → 可视差的 3D | 分层、不闭合、不能生长；本文阶段 1 是它的闭合版本 |
| 360° 深度全景 | 和阶段 1 的径向壳一样 | 只能站在中心看；本文的壳可以继续展开、改拓扑 |
| Space carving / 基于可见性的 Delaunay 重建（Labatut 2009 等） | "自由空间的边界就是表面"这一思想 | 纯几何，没有外观，不可微，不能渐进；本文把它变成生长的驱动力 |
| MODL（2026-11） | 从闭合网格（SfM 凸包）开始，可微优化，水密 | 只做物体（相机在外面），不能改亏格，没有无穷远/内部视角，没有渐进 |
| Meshtryoshka（2026） | 闭合的壳 | 多层嵌套壳从 SDF 每步重新提取，4 小时；本文是一张壳持续变形 |

可以声称为新的东西（需要再做一次文献检索确认）：**以"相机所在自由空间的边界"为唯一表示**，用齐次坐标把内部视角、外部视角和无穷远统一起来，从一张照片到多张照片**渐进生长**，每个阶段都是闭合、标准、可交付的资产，增长由字节定价控制。

## 5. 这个原理解决不了 / 还没想清楚的事

1. **拓扑手术**（§3 阶段 3）：什么时候打通、什么时候掐断，判据必须是通用的（不能按场景调参）。MODL 明确说自己不能改亏格；这里是最可能卡住的地方。
2. **薄的、毛茸茸的东西**（树叶、草、头发、栏杆）：一张不透明的闭合表面画不出视差正确的毛发。在本原理内部最自然的延伸是"部分自由的空间"——壳在那里是一层带 alpha 的膜（光线有一部分穿过去）。v1 先不做，量出它在各数据集上丢了多少。
3. **视角相关效果**（反光、高光）：标准材质只有有限的视角相关性。v1 用纹理 + 轻量视角项，量出损失。
4. **动态内容**：记忆的主角常常是人，而人在动。v1 只做静态场景，但这一条必须写进长期目标。
5. **单张照片的背面**：阶段 1 的光滑膜是"诚实的未知"。要不要用生成模型补全，是产品选择，不是本原理的一部分。
6. **画质上限**：之前的实验（P2 / P2b）说"单张不透明表面比 soup 低 2–5 dB"，但那两个实验是 **1 spp、没有抗锯齿**渲染的（texture_refit_v2.py 没有 dr.antialias，而 MeshSplatting 训练和评估都是 4× 超采样），几何也是冻结的粗 TSDF。这个结论在重新测之前不能作为"闭合表面不行"的证据。

## 6. 最小实验（先审 CPU 链路，再上 GPU；每个都有通过标准）

| 编号 | 内容 | 回答的问题 | 代价 | 通过标准（初版） |
|---|---|---|---|---|
| E0 | P2b 加 4× 超采样重测（lego，原有链路加一个开关） | 闭合不透明表面的画质上限到底差多少 | ~0.35 GPU-h | 不透明 soup 与软混合 soup 的差距 < 1 dB ⇒ §5.6 的旧结论作废 |
| E1 | 单张照片 → 前馈深度 → 径向壳（阶段 1），房间场景各取一张图 | 1 张照片的"3D 记忆"能否在 10 s 内、几 MB、零洞 | < 0.2 GPU-h | 任意视角零未覆盖像素；拍摄视点 PSNR ≥ 35 dB（≈ 照片本身）；文件 ≤ 5 MB |
| E2 | Room 全部视角，只做阶段 1（径向壳，优化 ρ + 纹理，4× 超采样） | 一个星形壳能解释多少；剩下的误差在哪里（应集中在遮挡区） | ~1 GPU-h | 误差热图显示损失集中在被遮挡区域 ⇒ 阶段 2 的必要性和位置被量出来 |
| E3 | lego，外部视角：物体球 + 背景壳，收缩包裹 | 外部模式 + 亏格问题有多严重 | ~0.5 GPU-h | 量出亏格错误导致的 PSNR 损失，决定阶段 3 的优先级 |

E0 不依赖新代码，最先做。E1–E3 共用一套小代码：球面网格 + ρ 参数化 + nvdiffrast（带 antialias + 超采样）+ ByteMesh 的 size probe。

## 7. 需要你决定的事

1. **质量的定义**：是否接受"按观看可能性加权的保真度"（拍摄点附近像照片，别处合理）作为主指标，而不是测试集平均 PSNR？这决定了论文怎么写、和谁比。
2. **v1 的输入**：从单张照片开始（E1，最像"照片的替代品"），还是从多视角视频开始（E2，最像现有 benchmark）？
3. **v1 的范围**：毛发/植被（§5.2）和动态（§5.4）先不做，可以吗？
4. **第一步**：先跑 E0（0.35 GPU-h），还是先写 E1–E3 的代码（CPU，约一天）？
